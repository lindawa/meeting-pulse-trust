# Questions, concerns and requests

Use a channel appropriate to the information you need to share.

## Pilot access and meeting information

Contact the deployment owner through your organization's private support channel
for pilot access, an account issue, a copy of meeting information, a deletion
request or a question about permitted data.

Describe the request privately and identify which information is involved. Ask
whether it concerns the application record, a Webex artifact, a delivered message,
a backup or an AI provider. Different systems can have different access and
retention requirements.

## General documentation questions

For a non-sensitive correction or question about these pages, use the
[documentation issue tracker](https://github.com/lindawa/meeting-pulse-trust/issues).
Do not include real meeting titles or links, transcripts, participant details,
screenshots containing customer data, credentials or private infrastructure
information.

## Security concerns

Report a suspected vulnerability privately using
[GitHub private vulnerability reporting](https://github.com/lindawa/meeting-pulse-trust/security/advisories/new).
Share the minimum necessary information and do not publish live credentials,
customer information or private meeting content in a public issue.

This project channel does not replace your organization's incident-response or
privacy process. Use that process for an active incident or regulated request.

## About this documentation

These are original project disclosures for Meeting Pulse / AI Meeting Delegate.
They are not an official Cisco product Privacy Data Sheet, a legal opinion or an
approval to use any particular information. The current application hosting
statement describes the Cisco on-premises pilot, not all possible deployments.

The public site contains documentation only. Neither application repository nor
the private source-evidence checklist is published here.
